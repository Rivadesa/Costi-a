## Cómo se trabaja la PWA (importante: aquí sí hay verificación local)

`frontend/pwa` — Vue 3 + TypeScript + Vite; dependencias de ejecución: `vue` y `@microsoft/signalr` (añadir otra exige motivo). A diferencia de .NET, **se compila y se prueba en local** con Node (22+): `npm ci`, `npm test`, `npm run build`.

**Verificación visual** (ha cazado tres fallos reales antes del primer push: `hashchange` del QR con la app ya abierta, WebSocket que ni conecta ni falla, y `fetch` invocado con receptor = *Illegal invocation*, que habría dejado toda orden "sin confirmar" para siempre): `npm run dev -- --port 5179` (el proxy de Vite manda `/api` a `http://127.0.0.1:5088`, con WebSocket) y, como no hay motor .NET local, un **simulador mínimo en Node** escuchando en `127.0.0.1:5088` que sirva `/api/native/v1/session`, `/board`, `/configuration`, `/catalog`, `/auth/hub-token`, `POST …/commands/*` (idempotente por `Idempotency-Key`, devolviendo la clave en la cabecera de eco) y `GET /commands/{key}`, con un interruptor para "perder" la siguiente respuesta (aplicar y cortar el socket). Se siembra la credencial en IndexedDB (`costina` → almacén `device`, clave `credential`, `{token:'dev.…', deviceName, pairedAt}`) y se recarga. El simulador es desechable: **no entra en el repositorio**.

Pirámide de pruebas: vitest (local y CI) → `dotnet/tests/http/pwa_http.py` (servidor real) → Playwright/Chromium contra el motor real (`COSTINA_E2E=1`, solo CI), que además inspecciona **cada JSON que recibe el navegador** (cero claves económicas) y la consola (cero violaciones de CSP).
