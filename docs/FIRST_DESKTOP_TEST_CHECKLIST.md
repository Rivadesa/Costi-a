# Checklist — primera prueba de escritorio

Versión objetivo inicial: **0.1.x demo**.

## Instalación

- [ ] El instalador abre en Windows 10/11.
- [ ] La instalación finaliza sin errores.
- [ ] Se crea acceso a Hospitality OS.
- [ ] La aplicación abre sin navegador.
- [ ] La ventana se adapta correctamente a 1366×768 o superior.
- [ ] SmartScreen, si aparece, se identifica como consecuencia esperada de un build de desarrollo sin firma.

## Entrada demo

- [ ] Se ve claramente **Entrar en modo demo**.
- [ ] No pide servidor ni credenciales.
- [ ] Tras entrar se muestra “Modo demo local”.
- [ ] Aparecen las mesas demo.

## Sala

- [ ] Se identifica de un vistazo mesa, PAX, pase y estado.
- [ ] Una alergia crítica destaca suficientemente.
- [ ] Abrir una mesa nueva resulta intuitivo.
- [ ] Abrir mesa requiere pocos pasos.
- [ ] El botón principal de la mesa es obvio.
- [ ] Enviar el siguiente pase es una acción rápida.
- [ ] Marcar servido es claro.
- [ ] Añadir bebida/extra resulta rápido.
- [ ] La cuenta provisional se entiende.

## Restricciones

- [ ] Se entiende la diferencia entre alergia, intolerancia y preferencia.
- [ ] Se puede indicar severidad crítica.
- [ ] La restricción queda asociada a un PAX concreto.
- [ ] Cocina ve texto explícito, no solo color.

## Cocina / KDS

- [ ] Cambiar entre partidas resulta rápido.
- [ ] Mesa y número de pase se leen a distancia.
- [ ] INICIAR y LISTO tienen tamaño suficiente.
- [ ] Restricciones del PAX destacan.
- [ ] El tiempo transcurrido se entiende.
- [ ] No se puede validar un pase si otra elaboración obligatoria sigue pendiente.
- [ ] Cuando todo está listo se entiende la acción VALIDAR PASE LISTO.

## Ritmo real de servicio

Anotar especialmente cualquier caso que no encaje:

- [ ] adelantar un pase;
- [ ] retrasar/pausar mesa;
- [ ] cambiar mesa;
- [ ] cambiar PAX;
- [ ] sustituir una elaboración;
- [ ] saltar un pase;
- [ ] pase extra del chef;
- [ ] compartir/combinar elaboraciones;
- [ ] adaptar solo a un comensal;
- [ ] comandas especiales de bebida.

## Preguntas de validación

1. ¿Podría sala usarlo durante un servicio sin volver al papel o a gritar a cocina?
2. ¿Podría cocina dejar el KDS visible durante todo el servicio?
3. ¿Qué información sobra?
4. ¿Qué información falta?
5. ¿Qué acción necesita demasiados clics?
6. ¿Qué término no coincide con la forma de hablar del equipo?
7. ¿Qué excepción real no está representada?

## Resultado

No evaluar solo “me gusta/no me gusta”. Registrar cada hallazgo como:

- pantalla;
- acción que se estaba intentando realizar;
- comportamiento esperado;
- comportamiento observado;
- severidad: bloqueante / alta / media / mejora.
