# D0 — Contrato de transición y separación del ciclo de servicio

Base verificada: develop 297fa596a7ff29010ab6fc3d2aec5706fd5d813b. Autorización del usuario: desarrollo fase a fase, 2026-09-15. Relación: PR #19 (plan), issue #17 (defecto).

## Corte realizado

ADR-008 acepta arquitectura destino .NET/WPF/PostgreSQL y clientes Vue PWA, sin Docker obligatorio en instalación. ADR-009 define tres ejes independientes. El código de referencia PHP se corrige una sola vez para fijar comportamiento y conservar datos antes del port .NET; no se añaden módulos ERP legacy.

Implementación: estados de ocupación y liquidación, cierre/reapertura de cuenta, finalización/liberación independientes, control de versiones existente, permisos nuevos, auditoría transaccional de mutaciones del servicio, recuperación de cuentas de mesas ya liberadas, migración con archivo de estados anteriores, bloqueo de estados ambiguos y revisión autorizada.

No se ha creado ni instalado aún el servidor .NET, WPF o un EXE nuevo. La demo local simulada no se modifica. Esta fase no es autorización de piloto.

## Pruebas reproducibles

Sin dependencias:

```sh
cd backend
php tests/run.php
php tests/application.php
php tests/projections.php
php tests/lifecycle.php
```

Con las dependencias bloqueadas y PostgreSQL de pruebas:

```sh
composer test
php tests/integration.php
php tests/reliability.php
APP_ENV=testing php tests/lifecycle-migration.php
```

`lifecycle-migration.php` usa un schema desechable generado en la base de PRUEBAS, conserva/restaura search_path y elimina únicamente ese schema al terminar. Prueba el esquema viejo real, los ocho estados, pago/respuesta idempotente históricos y aborto de duplicados. Nunca ejecutar contra datos del restaurante.

Pruebas HTTP nuevas: pago temprano persistido, saldo parcial/total, permisos diferenciados, bloqueo del cierre antiguo, finalización y liberación idempotentes, auditoría con usuario, consulta de cuentas liberadas, segunda apertura de mesa ocupada rechazada. El smoke HTTP existente sigue probando reinicio y catálogo.

## Puerta de salida D0

Revisar CI del commit exacto, no reutilizar un verde antiguo. Requiere backend + pruebas de migración/PG + smoke del paquete HTTP. El cliente antiguo no ofrece todavía las nuevas acciones; no distribuirlo como cliente D0. La validación física y un instalador nativo pertenecen a D1/D2.
