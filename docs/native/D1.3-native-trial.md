# D1.3 — Instalador y asistente de ensayo nativo

Fecha: 2026-09-16. Base: D1.2 `25d62f9`, PR #22. PR encadenada; no modifica develop/main ni la instalación previa.

## Entrega
NSIS por usuario instala cliente WPF, motor .NET y binarios PostgreSQL 17.11. Asistente WPF prepara una base dedicada, genera seis secretos independientes, usa SCRAM, protege configuración con DPAPI CurrentUser y ACL, inicia procesos y abre el cliente con una sola clave de rol heredada. El cliente borra esas variables de su entorno y usa la autenticación HTTP normal; no se añaden bypasses ni endpoints de control privilegiado.

El inicio normal no migra ni carga semillas. PostgreSQL y API se enlazan exclusivamente a loopback. No registra SCM ni autorun: ver ADR-010. Producción mantiene como objetivo servicios Windows con identidad, credenciales, TLS, backups y recuperabilidad probados. El supervisor es una etapa de ensayo visible, no el producto de alta disponibilidad.

## Fronteras
Solo `native_d1` en una base dedicada terminada en `_d1_lab`. Contrato HTTP operativo/económico permanece igual. Cambio de transporte interno: cuando el motor está explícitamente supervisado, cierre de su stdin o STOP en esa tubería solicita parada limpia. No expone un endpoint de parada. La clave del cliente se pasa únicamente al proceso hijo, sin argumentos de línea ni ficheros claros; el servidor asigna el rol.

`Costina.TrialHost` separa instalación de WPF; `Costina.Launcher` solo coordina sus acciones. Roles PostgreSQL: bootstrap crea DB/roles, owner inicializa schema, runtime tiene SELECT/INSERT/UPDATE específicos y no puede borrar auditoría ni alterar esquema. El dueño Windows de este laboratorio controla todos los roles; aún no es seguridad multiusuario/terminal productiva.

## Pruebas
`Costina.TrialChecks` solo corre en CI Windows aislado. Instala el paquete, inicializa PostgreSQL nativo, abre ventana WPF real, ejecuta pases y consumo/pago mediante botones, valida acceso sala, reinicia DB/motor y comprueba persistencia, bloqueo exclusivo, configuración cifrada, permisos del runtime y colisiones de puerto. El job también ejecuta desinstalación sin borrar datos. Las suites anteriores se conservan. Una ejecución verde no certifica PC físico, LAN ni servicio Windows.

## Fuentes de distribución
- https://www.postgresql.org/download/windows/ — binarios para incluir en otro instalador.
- https://www.enterprisedb.com/download-postgresql-binaries — PostgreSQL 17.11.
- https://get.enterprisedb.com/postgresql/postgresql-17.11-3-windows-x64-binaries.zip — versión exacta, no latest flotante.
- https://www.postgresql.org/docs/17/app-initdb.html — autenticación/archivo temporal.
- https://www.postgresql.org/docs/17/app-pg-ctl.html — arranque/parada e independencia respecto de SCM.
- https://devblogs.microsoft.com/cppblog/c-runtime-deployment-why-choose-applocal/ — distribución local del runtime C++.
- https://nsis.sourceforge.io/Reference/RequestExecutionLevel — instalador por usuario sin elevación.

El build registra hash del ZIP EDB descargado por HTTPS, no afirma verificación con checksum firmado por proveedor. Los runtimes C++ se obtienen del directorio REDIST de Visual Studio del runner, no de sitios de DLL. Revisar licencias/avisos y actualizaciones antes de distribución comercial; el paquete sigue siendo interno/de ensayo. El CI debe fallar si falta un componente o artefacto.
