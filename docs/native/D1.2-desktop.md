# D1.2 — primera interfaz Windows nativa

Fecha: 2026-09-16. Rama `feat/d1-wpf-client`, basada en D1.1 `f26ad017`. Código de ensayo, no migración de la instalación Laravel/Tauri ni piloto operativo.

## Qué cambia
Cliente C#/WPF con biblioteca HTTP separada: conexión a la API real, mesas/menú desde configuración persistida, pases y preparaciones, pausa/servido/fin/liberación explícitos. Cuenta/Caja es otra pestaña y requiere rol `main` asignado por el servidor. El catálogo se lee en su endpoint protegido; al añadir solo se envían identificador y cantidad, nunca un precio libre. Las cuentas abiertas de mesas liberadas siguen accesibles.

Cuatro lecturas adicionales de API (`session`, `configuration`, `checkout/catalog`, `checkout/accounts`) reutilizan el middleware y los permisos existentes. Consultas SQL parametrizadas por tenant/empresa/local; configuración operativa sin precios. Ningún cambio de esquema ni del dominio de D1.1.

## Uso del cliente compilado
Extraer TODA la carpeta del ZIP del cliente y abrir `Costina.Desktop.exe`. No separar el ejecutable de sus bibliotecas. No requiere instalar .NET SDK, Node ni Docker. Sin servidor puede comprobarse el arranque y la pantalla de conexión; no hay un modo de simulación que aparente guardar datos.

Para trabajar hay que arrancar el motor D1.2 emparejado y PostgreSQL nativo en un entorno de ensayo. Conserva las variables de instalación D1.1 (`COSTINA_LAB_MODE`, `COSTINA_DB`, ámbito, puerto y tres claves aleatorias distintas). Base aislada terminada en `_d1_lab`; inicialización explícita `Costina.Server.exe init-lab` una vez. El arranque normal es `Costina.Server.exe` sin argumentos y no reinicializa. La clave se introduce en la aplicación, se verifica en el servidor y no se guarda en disco. Nunca enviar claves a una conversación ni publicarlas en GitHub. El instalador que automatiza el servidor/PostgreSQL sigue pendiente; no se presenta este ZIP como instalador completo.

Usar `http://127.0.0.1:5088` (o el puerto configurado). La aplicación y el motor solo aceptan conexiones de este PC en este corte; no abrir puertos para tablets todavía. El antiguo motor D1.1 no tiene las cuatro lecturas nuevas. No mezclar binarios.

## Prueba manual
1. Abrir un servicio desde las mesas y el menú que devuelve el servidor.
2. Iniciar, enviar pase, iniciar y terminar cada elaboración, validar y servir.
3. En Cuenta/Caja, seleccionar un producto del catálogo y registrar un pago ficticio; volver a servicio y continuar cocina.
4. Terminar los pases, completar el servicio y liberar la mesa indicando motivo; conservar la cuenta sin liquidar.
5. Cerrar/abrir cliente y reiniciar motor sin repetir inicialización. Comprobar datos.
6. Abrir otro cliente con rol de sala/cocina; comprobar restricciones de interfaz y API. Pulsar Actualizar: no hay realtime automático en este corte.

## Límites
Autenticación por claves de laboratorio, no usuarios/dispositivos definitivos. Refresco manual. Orden pendiente retenida en memoria durante esta sesión; cierre forzado pierde el reintento. No cola durable, SignalR, TLS/LAN, instalador completo, backup/restauración, fiscalidad, inventario, bonos ni migración de datos. No hay gestión completa de alérgenos en el nuevo motor: solo datos ficticios, nunca servicio real. Code-behind de presentación acotado a este corte; siguiente refactor antes de ampliar pantallas: viewmodels y comandos enlazados, sin trasladar negocio al cliente.
